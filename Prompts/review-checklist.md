# 代码审查清单

## 功能正确性

- [ ] 实现是否符合功能规格中的验收标准
- [ ] 边界条件是否正确处理
- [ ] 错误场景是否有合理的处理
- [ ] 是否有未处理的异常路径

## 代码质量

- [ ] 代码是否清晰易读
- [ ] 命名是否准确反映用途（变量、函数、类）
- [ ] 是否遵循 Python PEP 8 / PEP 257 规范
- [ ] 是否有不必要的复杂度（可简化的逻辑）
- [ ] 是否有重复代码可提取为公用函数

## 类型安全

- [ ] 函数签名是否有完整的类型注解
- [ ] 是否通过 mypy strict 检查
- [ ] 是否合理使用 Optional / Union 等类型

## 测试覆盖

- [ ] 核心逻辑是否有对应的单元测试
- [ ] 边界条件和错误路径是否有测试
- [ ] 测试是否独立、可重复执行
- [ ] 测试命名是否清晰描述了被测场景

## 安全性

- [ ] 是否存在注入风险（SQL、命令、路径）
- [ ] 敏感信息是否正确处理（不硬编码、不打日志）
- [ ] 外部输入是否有验证

## 性能

- [ ] 是否有明显的性能瓶颈
- [ ] 大数据量场景是否考虑了内存和时间复杂度
- [ ] 是否有不必要的 I/O 或网络请求

## 依赖与兼容性

- [ ] 新增依赖是否必要、版本是否合理
- [ ] 是否兼容项目要求的 Python 最低版本
